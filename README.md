# SPIES

Free community site for sharing trading templates for MotiveWave, Sierra Chart and Quantower.

Live: https://spies.spies-4082fd.workers.dev

## How it works

- **Site:** Next.js on Cloudflare Workers (free plan).
- **Data:** Supabase free plan for the database, logins, file storage and the `process-upload` function.
- **Uploads:** files land in a private quarantine bucket. The `process-upload` function checks each file's real format, so a renamed `.exe` is rejected.
- **Scans:** ClamAV runs on GitHub Actions every 5 minutes. A file can only be downloaded while its stored hash matches the hash that was scanned clean.
- **Publishing:** a listing goes live once its files pass the scan. Admins can switch to manual approval and remove anything later.
- **Bot protection:** Cloudflare Turnstile on signup, login and forms.

Uploaded files are never run on the server or installed on anyone's computer.

## Deploying

Every push to `main` deploys through `.github/workflows/deploy.yml`. It needs two repository secrets:

| Secret | Where |
| --- | --- |
| `SUPABASE_ACCESS_TOKEN` | supabase.com/dashboard/account/tokens |
| `CLOUDFLARE_API_TOKEN` | Cloudflare token with Workers Scripts Edit, Turnstile Edit and Account Settings Read |

Everything else comes from `spies.deploy.json` or is generated by `scripts/ci-setup.mjs`. Nothing here can turn on billing.

| Workflow | When | What |
| --- | --- | --- |
| `deploy.yml` | push to main | migrations, function, auth settings, Worker |
| `scan.yml` | every 5 min | ClamAV scan of waiting files |
| `keepalive.yml` | daily | keeps the free database awake |
| `ci.yml` | push | lint, types, tests, build |

**Email:** Supabase's free mailer only reaches the project team, so new accounts are active right away. To turn on confirmation and password reset emails, add SMTP in Supabase (Brevo or Resend are free) and set `emailConfirmation` to `true`.

**Admin:** sign up, then run `update public.profiles set role = 'admin' where username = '...';` in the Supabase SQL editor.

## Local development

Needs Node 22 and Docker.

```bash
npm install
npx supabase start
cp .env.example .env.local      # fill in from `npx supabase status`
cp supabase/functions/.env.example supabase/functions/.env
npx supabase db reset
npm run functions:serve         # second terminal
npm run dev                     # http://localhost:3000
```

Tests: `npm run check` (lint, types, unit tests, build), `npm run test:integration` and `npm run test:e2e` (both need the local stack).

Manual scanning: [docs/MANUAL_SCANNING.md](docs/MANUAL_SCANNING.md).

## Adding a platform

1. Insert it into `public.platforms` in a new migration.
2. Add its file formats to `FORMATS` and `PLATFORM_FORMATS` in `supabase/functions/_shared/formats.ts`.
3. Add its label and install hints in `src/lib/catalog.ts`.
